# 交给 Windows Codex 的实施任务

下面整段可复制到 Windows 上的 Codex。执行前，请补充 Windows 项目目录。不要把账号密码、订阅链接或设备清单复制进公开任务、提交或日志。

---

请在 NAS Device Flow 的现有仓库里开发 Windows 独立部署版。目标是让一台持续开机的 Windows 电脑承担局域网旁路由职责，替代 NAS 作为设备分流宿主；同一 Wi-Fi 或有线局域网的设备接入后，由网页按设备开启或关闭智能代理。不是一个连接远程 NAS 的桌面壳，也不只是给 Windows 本机设置代理。

先读取仓库的 AGENTS.md、README、部署文档和现有代码。你与其他开发者共享仓库，不要覆盖或回退他人的更改。先检查 Git 状态，使用 `codex/` 前缀分支。先盘点现有实现，再确定复用与新增范围。不要复制用户私有部署目录里的密码、节点、设备 MAC 或 IP 清单到源码。文档使用示例值。

## 架构与先决条件

优先评估具有桥接网络的 Linux 虚拟机，复用现有 Linux 容器后端、Mihomo 和设备管理逻辑。核实当前 Windows 版本、CPU 虚拟化、Hyper-V 或其他已安装虚拟化平台、网卡及交换机能力、桥接限制、防火墙和现有 VPN。不要假定 Docker Desktop 的 Linux VM 能像原生 Linux 一样直接使用物理 LAN macvlan。发现不支持时明确说明，不要用 NAT 网络冒充全局域网网关。

给出实际可用的网络路径：终端如何通过宿主或虚拟机访问网关、DNS、透明代理以及上级路由。说明宿主、虚拟机、面板、代理核心各自的地址与职责。固定地址必须先做冲突检测，并避开 DHCP 地址池；不要在未核对现场时使用固定的私网 IP。识别 Windows 多网卡、Wi-Fi、有线、Tailscale、Cisco、UU 和其他代理软件的路由影响。不要凭设备名称合并 MAC 身份，不要假定无线网卡能够满足透明桥接。

桥接部署、宿主长期运行和睡眠策略会影响全网可用性。先提供只读预检和明确的可行性结论，再进行网络切换。涉及虚拟交换机、物理网卡绑定或网关接管时，说明断线风险并让用户在切换前确认；必须留下不依赖当前网络会话的回退步骤。不得重置路由器、删除网卡、关闭防火墙或关闭安全软件作为默认解决办法。

## 自动接入与分流

复用设备管理、代理白名单、默认新设备规则、订阅切换及重命名、状态显示、流量统计、登录、语言和深色模式。兼容现有后端 API 和配置迁移，不要维护一个行为不一致的副本。需要更改共享后端时，增加迁移与回归测试，保持 NAS 部署可运行。

设备开启代理时执行国内直连、其他目标按规则代理；关闭时走直接转发。页面开关状态不能冒充已验证的端到端网络状态。只在实际观测到租约或流量时声称已接管。测试新设备默认规则，IP 租约变化和 MAC 私有地址变化，保留未知设备供人工识别。允许用户明确合并或归档旧记录，提供恢复办法，避免按名称自动继承代理权限。

DHCP 必须有单一、明确的权威。检查现有 DHCP 服务器、租约、DNS、IPv6 RA/RDNSS 和客户端实际网关。不要直接关闭主路由 DHCP 或 IPv6，更不要同时运行两个未协调的 DHCP 服务。先在隔离测试网络验证方案，再制定正式切换和回退。若需要关闭现有 DHCP，必须先确认替代服务已就绪，并获得用户对具体切换的确认。IPv6 无法正确接管时，说明其路径和限制，不能让客户端静默绕过策略。

## 安全与故障恢复

实现首次设置、登录、密码更改、CSRF 防护和请求校验；凭据保存在私有运行数据中，不进入 Git。面板默认仅局域网可达，不自动开公网端口。优先支持有效证书的 HTTPS；使用 HTTP 时清楚说明局域网中的凭据风险。不要绕过证书校验。

网络变更前保存当前网卡、路由、DNS、DHCP、虚拟机与防火墙状态，备份应用配置。写出可离线执行的回退脚本或步骤，并实际验证能够恢复原网关和 DNS。部署脚本应幂等，避免重复添加规则。启动失败、Mihomo 配置校验失败、订阅不可达、宿主重启、虚拟机关闭和网卡变化时，应给出可操作的错误信息。不要在失败后继续让 DHCP 下发一个不可用网关。

恢复方案应区分“恢复基本上网”和“恢复代理”。不要让管理面板、诊断通道和全网网关同时依赖一个无法回退的变更。不得无提示地续租所有设备、清除会话或重启整个家庭网络。

## 安装、测试与交付

提供普通用户能完成的 Windows 安装流程：先决条件检查、虚拟机或项目导入、浏览器首次设置、试运行、正式接管、升级和卸载。自动化可重复步骤，但不要静默启用会导致重启或网络中断的 Windows 功能。对缺少 Hyper-V 的版本提供经过验证的替代路线，或明确当前不支持；不要承诺未经测试的平台。

至少验证：后端测试通过；配置校验失败不覆盖工作配置；登录与权限保护有效；设备开关分别改变真实流量；国内、海外、DNS 和 UDP 路径；未知设备默认规则；DHCP 唯一性；私有地址与租约变化；订阅更新后保留用户规则；重启后恢复；卸载回退后终端能够正常直连。不可在当前网络完成的测试，明确标为未验证。

不要把链路聚合的两个 2.5GbE 网口简单宣称为单连接 5Gbps；吞吐量需要实测，交换机聚合模式、端口对、宿主聚合模式与 SMB 多通道分别核对。

交付源码、安装包或可重现构建脚本、双语安装说明、版本号、CHANGELOG、测试结果、已知限制和回退文档。保持产品主功能是按设备分流，图表和订阅管理不应遮挡设备开关。先完成本地验证，再整理可评审的提交和发布说明。未经用户另行授权，不发布 GitHub Release、不上传私有配置、不改生产路由器、不进行公网开放。

请先汇报预检发现和选定架构，随后完成已授权的开发、测试和文档工作，不要只给出方案。遇到需要用户操作的网络切换时，先完成其他不依赖切换的开发，提供具体待验证产物与回退办法后再请求操作。
